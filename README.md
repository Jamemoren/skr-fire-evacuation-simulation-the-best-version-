# ระบบจำลอง 3 มิติ เพื่อคำนวณและเพิ่มประสิทธิภาพเส้นทางการอพยพกรณีฉุกเฉิน ลดปรากฏการณ์คอขวดด้วยหลักคณิตศาสตร์

**อาคารเรียน 1, 3 และ 4 โรงเรียนสวนกุหลาบวิทยาลัย รังสิต**

อัปเดตผังตามภาพอ้างอิง: พื้นปูนสีเทา กำแพงปูนสีขาว ลานจอดรถว่าง หอพระหันตะวันตก และโมเดลตึก 3–4 พร้อมทางเชื่อม (ปัจจุบันอยู่ชั้น 3 ตามคำขอล่าสุด) อ่านรายละเอียดและผลตรวจใน [CAMPUS_CONCRETE_UPDATE.md](CAMPUS_CONCRETE_UPDATE.md)

โครงการนี้เป็นแบบจำลองดิจิทัลสำหรับศึกษาการอพยพของผู้ใช้อาคารในสถานการณ์ไฟไหม้ โดยจำลองประชากรสูงสุด 3,000 คน ตั้งแต่ห้องเรียน ทางเดิน ประตู บันได ทางออกอาคาร จนถึงจุดรวมพลบริเวณสนามฟุตบอล

## เริ่มต้นเร็ว (สำหรับกรรมการและผู้ใช้ใหม่)

```bash
npm install
npm run dev          # เปิด http://localhost:5173 — ไม่ต้องรันเซิร์ฟเวอร์มือถือก็ใช้ได้ครบ
```

ข้อความ `http proxy error: /api/health … ECONNREFUSED 127.0.0.1:8787` ใน terminal หมายถึงยังไม่ได้รันเซิร์ฟเวอร์มือถือ (`npm run server:lan`) — ไม่กระทบหน้าจำลอง หน้าเว็บใช้ “จำลองในเบราว์เซอร์” แทนอัตโนมัติ

**เส้นทางแนะนำสำหรับกรรมการ (ประมาณ 5 นาที)**

1. กด **นำเสนอ** ที่แถบบน → **▶ เริ่มการสาธิต** — กดครั้งเดียว ดูต่อเนื่องจนจบ (~3½ นาที): ห้อง 203 → กราฟ → สูตรและการแทนค่า → จุดที่คำตอบเปลี่ยน (28 คน) → ไฟปิดทาง → สรุป และ “ลองปรับจำนวนคนรอเอง” (รายละเอียดด้านล่าง)
2. แถบล่าง: ⏮ ย้อนช่วง · ❚❚/▶ พัก/เล่นต่อ (Space) · ⏭ ช่วงถัดไป · ปิดเสียง (M) · ✕ ออก (Esc) — พักแล้วกล้อง ตัวเลข เส้นบนโมเดล และเสียงหยุดพร้อมกัน
3. ทางเลือก **ดูแบบสไลด์ (เลื่อนเอง)**: สไลด์ 6 “ผลเปรียบเทียบ” อ่านจาก `public/presentation/results.json` (รันระบบจำลองจริง พร้อมวันที่ seed และคำสั่งรันซ้ำ) · สไลด์ 8 กด **▶ ชมการสาธิตอัตโนมัติ** ของตัวแก้ไข
4. ออกจากโหมดนำเสนอ แล้วกด **เริ่มการจำลอง** เพื่อดูของจริง

**คู่มือ** (ปุ่ม “คู่มือ”, เปิดเองครั้งแรก): เลือก “อ่านตามหัวข้อ” (14 บท พื้นฐาน → ขั้นสูง ค้นหาได้ จำบทที่ค้าง) หรือ “ลองทำบนหน้าจอจริง” (ชี้ปุ่มจริงและรอให้กด) — แต่ละบทบอก ทำไม → กดที่ไหน → จะเห็นอะไร → ตรวจอะไร

**เสียง**: ตัวจัดการเสียงเดียว (`src/audio/soundManager.ts`) สำหรับ Intro เสียงพื้นหลัง เอฟเฟกต์ และเสียงบรรยาย ถ้าเบราว์เซอร์บล็อก autoplay จะเริ่มเมื่อคลิก/แตะครั้งแรก ปุ่มลำโพงที่แถบบนจำค่าไว้ (ถ้าปิดไว้ คลิกครั้งแรกจะไม่เปิดเสียง) ข้อความบนจอสื่อสารครบแม้ปิดเสียง

### การสาธิตคณิตศาสตร์ (“เริ่มการสาธิต”)

เรื่องเดียวบนโมเดลจริง: “ถ้าบันไดกลางมีคนรอมากขึ้น เราควรเปลี่ยนไปใช้บันไดอีกทางเมื่อไหร่?” — 6 ช่วง 27 จังหวะ ตัวเลขทุกตัวคำนวณสดตอนเปิด จากโค้ดชุดเดียวกับระบบจำลอง

| ช่วง | บนโมเดล | ในสมการ / แผง |
|---|---|---|
| 1 ตั้งโจทย์ | ซูมห้อง 203 → Zone C → เผยทาง A แล้ว B | คำถาม ระยะของแต่ละทาง |
| 2 กราฟ | Node ปรากฏตามลำดับการเดิน (ชนิดจากข้อมูลจริง) → Edge → เน้นบันไดกลาง ชั้น 2→1 | ความหมายของ Node/Edge ข้อมูลของเส้น (d, w, c, v) |
| 3 สูตรและการแทนค่า | ป้าย d, v บนบันไดมีเส้นชี้ไปยังค่าในสมการ · เส้นที่กำลังบวกสว่างบนโมเดล | สูตรเต็มแยกสีตามพจน์ (มีชื่อกำกับ) → ตัดพจน์ที่เป็นศูนย์ → แทนค่า → 21.930 → ยอดสะสม A = 168.196 ✓ · B: ช่วงนอกอาคาร 77.037 → 193.320 ✓ · ตารางทุกช่วง (ชี้แถวแล้วเส้นบนโมเดลสว่าง) |
| 4 จุดเปลี่ยน | ทาง A เป็นสีอำพันเมื่อมีคิว · ที่ 28 คนทาง B สว่าง | L × (1/4.5 + 20/(2.2×13.2317)) = L × 0.90928 · กราฟต้นทุนตาม L · ที่ 27 คนโปรแกรมเลือก A (192.747 < 193.320) ที่ 28 คนเลือก B (193.656 > 193.320) |
| 5 ไฟปิดทาง | 2 เส้นในเปลวไฟเป็นเส้นประแดง “ตัดออก (∞)” → ทางใหม่ลงบันไดซ้าย | คิว = แพงขึ้นทีละน้อย · ไฟ = ใช้ไม่ได้ (คนละเงื่อนไข) · วิธีค้นหา A* ตามโค้ด |
| 6 สรุป | ผัง + กราฟ + เส้นที่เลือก | “ลองปรับจำนวนคนรอเอง” — สมการ กราฟ และเส้นบนโมเดลตามค่าที่เลือก (คำนวณแยกจากรอบจำลองหลัก) |

ที่มาของตัวเลข: `src/present/story/storyData.ts` เรียก `computeRouteExample()` (`src/explain/routeExample.ts`) ซึ่งใช้ `findPath` และ `stepCost`/`stepCostTerms` ของ `src/simulation/graph.ts` · ค่าที่แสดงในการแทนค่าเลือกจำนวนทศนิยมให้คำนวณซ้ำจากตัวเลขบนจอแล้วได้ผลเดียวกัน (d = 13.2317 ไม่ใช่ 13.23 ซึ่งจะได้ 21.927) · ผลรวมคิดจากค่าเต็มก่อนปัด · ลำดับจังหวะอยู่ใน `storyBeats.ts` ตัวเล่นใน `StoryPlayer.tsx`

ตรวจด้วย `npm run qa:route-example` (S1–S9: การแทนค่าบนจอ = stepCost, 27→A/28→B ด้วย findPath, กราฟตรงกับ findPath ทุกค่า 0–40, ต้นทุน A เพิ่ม L × 0.90928 พอดี, ไฟตัด 2 เส้นด้วย ∞, การปัดเศษ, ค่าคาดการณ์ของ A* ไม่เกินต้นทุนจริงทุกเส้น 1,031 ทิศ จึงได้ทางต่ำสุด) และ `python3 scripts/qa-experience.py story story-mobile story-reduced` (กดเริ่มครั้งเดียวจนจบ, พัก/เล่นต่อ/ย้อนช่วง, ตัวเลขบนจอ = โปรแกรม, ลองปรับเอง, จอ 390×844, ลดการเคลื่อนไหว)

### ตัวอย่างคำนวณ (ใช้ทั้งในคู่มือและสไลด์)

นักเรียนห้อง 203 (อาคาร 1 ชั้น 2) → จุดรวมพล Zone C · แนวทาง “สมดุล” (`src/explain/routeExample.ts` เรียก `stepCost` ตัวเดียวกับที่ระบบจำลองใช้)

```
ต้นทุนช่วง = 0.28·d + (d/v + L/c)·1 + 20·L/(w·max(4,d)) + 4200·ไฟ + 2436·ความร้อน + 1250·ควัน
d ระยะ (ม.) · v = 1.32 ม./วิ × ตัวคูณทาง (บันไดลง 0.55) · L คนที่วางแผนใช้ทางแล้ว · c ความจุ (คน/วิ) · w ความกว้าง (ม.)
```

| | A · บันไดกลาง | B · บันไดซ้าย |
|---|---|---|
| ระยะ | 153.4 ม. | 179.0 ม. |
| ต้นทุนรวม (มือ = โปรแกรม) | 168.196 | 193.320 |

ไม่มีไฟและคิว จึงเหลือ `0.28·d + d/v` ต่อช่วง ระบบเลือก A ตรงกับการคำนวณมือ · แต่ละคนที่รอบันไดกลางเพิ่มต้นทุน 1/4.5 + 20/(2.2×13.23) = 0.90928 → เปลี่ยนไปบันไดซ้ายเมื่อ L ≥ ⌊25.124/0.90928⌋ + 1 = **28 คน** ซึ่งโปรแกรมเปลี่ยนที่ 28 คนเช่นกัน · ไฟที่บันไดกลาง → เลี่ยงบันไดกลาง · ปิดทางออกชั้น 1 ทั้งหมด → “ไม่มีเส้นทาง” (ไม่สร้างทางเอง) ตรวจด้วย `npm run qa:route-example`

### ทดสอบส่วนประสบการณ์ใช้งาน

```bash
npm run qa:route-example        # ตัวอย่างคำนวณ มือ = โปรแกรม (7 ข้อ)

                                # เดโมอัตโนมัติ (กล้อง/พัก/ย้อน/ข้อมูลไม่เปลี่ยน), นำเสนอ (คีย์บอร์ด/สารบัญ/มือถือ/reduced motion/ไม่เรียก API)
```

`qa:experience` ต้องเปิด `npx vite --host 127.0.0.1 --port 5199` ไว้ และตั้ง `QA_CHROME` เป็นตำแหน่ง Chrome/Chromium ส่วน Safari/iOS ยังไม่ได้ทดสอบอัตโนมัติ (ติดตั้ง WebKit ในเครื่องทดสอบไม่ได้)

## ขอบเขตของระบบ

ระบบประกอบด้วยแบบจำลองอาคาร 9 ชั้น โครงข่ายเส้นทางอพยพ การจัดสรรประชากร ความจุของประตูและบันได การเกิดคอขวด การแพร่ของไฟและควัน แบบจำลองความร้อนเชิงประมาณ และการคำนวณเส้นทางใหม่เมื่อสภาพแวดล้อมเปลี่ยนแปลง

การเลือกเส้นทางพิจารณาทั้งระยะทาง เวลาในการเดิน ความหนาแน่น คิว ไฟ ควัน และอุณหภูมิ โดยยังคงข้อจำกัดทางกายภาพของอาคาร เช่น ประตูจริง ช่องบันได ทางเดิน และขอบเขตที่ไม่สามารถเดินผ่านได้

## การตรวจสอบ

การวาดภาพใช้แคชเมื่อคนและกล้องอยู่นิ่ง และส่งเฉพาะ instance matrices ที่ใช้งานจริง คุณภาพภาพ จำนวน NPC และรอบฟิสิกส์ยังใช้การตั้งค่าเดิม ตัวนับงานภาพอยู่ใน `canvas.dataset.simAgentWork` และ `canvas.dataset.simFireWork`

มีชุดตรวจสอบสำหรับโครงสร้างโครงการ ความถูกต้องของ topology ความสอดคล้องระหว่าง Semantic Map กับ Simulation Graph การเข้าถึงจุดรวมพล การหลบความร้อน การหลบสิ่งกีดขวางบริเวณทางเข้าสนาม และขอบเขตการลามของไฟ

รันชุดตรวจสอบแบบรวดเร็วด้วย:

```bash
npm run qa:fast
```

รันชุดตรวจสอบทั้งหมดด้วย:

```bash
npm run qa
```

ตรวจเฉพาะ regression ด้านความสูงโมเดล/ขอบเขตไฟ บัฟเฟอร์ภาพ การควบคุม pointer ขอบเขตการเดิน ผลคำนวณหลังปรับประสิทธิภาพ และ lifecycle ของการจำลองด้วย `npm run qa:audit` ดูผลตรวจล่าสุดและขอบเขตการทดสอบใน [QA_REPORT.md](QA_REPORT.md)

ชุด audit รวมการกดเริ่มซ้ำ พัก/ทำต่อผิดสถานะ reset แล้วเริ่มทันที ค่าตัวเลขไม่จำกัด ชั้นที่ไม่เป็นจำนวนเต็ม นาฬิกาวาดภาพเริ่มใหม่ เฟรมช้า การคืน pointer capture ประวัติท่าจากคนชุดเก่า การเปิดใช้งานนาน และ id จุดไฟหลังเพิ่ม/ลบอย่างรวดเร็ว

## การใช้งาน

ตัวละครใช้สัดส่วนสูง 1.58 เมตร มีชุดนักเรียนชาย/หญิง ใบหน้า ทรงผม และรายละเอียดเครื่องแต่งกาย สีผิวและสีผมต่างกันตามบุคคล แขนขาแกว่งและเข่างอเมื่อเคลื่อนที่จริง หยุดท่าตามเวลาจำลองเมื่อพัก และไม่เดินย่ำในคิว มุมภายในใช้รายละเอียดเต็ม ส่วนมุมรวมอาคารและโหมดประหยัดลดรายละเอียดที่มองเห็นยาก ทั้งหมดใช้ instancing ร่วมกันสองกลุ่ม

อนิเมชันใช้เวลาของเฟรมภาพเพื่อขยับต่อเนื่องระหว่างรอบฟิสิกส์ พร้อมเกลี่ยการเริ่ม/หยุดก้าวและมุมหันตามทางที่สั้นที่สุด มุมภายในมีท่าหายใจและขยับแขน/ศีรษะเบา ๆ ตอนรอ การเกลี่ยตำแหน่งเปิดเฉพาะก้าวสั้นบนพื้นที่เดียวกันที่ความเร็วจำลอง 1–2× และหยุดเกลี่ยตรงมุมหัก เปลี่ยนชั้น หรือหมดสติ โหมดเร่งเวลาจำกัดความถี่ก้าวให้ยังดูรู้เรื่อง การกดพักจะค้างท่าทั้งหมดและทำต่อจากท่าเดิม

นักเรียนแสดงในห้องก่อนเริ่มและหลังเริ่มใหม่ตามจำนวนที่เลือก เมื่อกดเริ่มการจำลองจึงเริ่มเคลื่อนที่และนับเวลา การเปลี่ยนชั้นหรือระดับกราฟิกไม่รีเซ็ตประชากร โหมดภายในชั้นแสดงเฉพาะคนบนชั้นที่เลือก

เมาส์บนคอมพิวเตอร์: คลิกซ้ายใช้กดปุ่ม เลือกในโหมดแก้ไข หรือวางไฟเมื่อเปิดโหมดวางไฟ การลากคลิกซ้ายไม่หมุนกล้อง คลิกขวาค้างแล้วลากเพื่อหันมองทั้งมุมโมเดลและโหมดเดิน ใช้ล้อเมาส์เพื่อซูม

มือถือและ iPad ใช้เมนูด้านล่าง: โมเดล / ตั้งค่า / ผลอพยพ / เหตุการณ์ และปุ่มเริ่มหรือหยุดพัก ลากหนึ่งนิ้วเพื่อหมุน สองนิ้วเพื่อซูมและเลื่อนฉาก ใช้ปุ่มอาคาร / สนาม / ด้านบนเพื่อกลับมุมหลัก และเปิดอาคารเพื่อเลือกชั้น

ตั้งค่า → ภาพและความลื่นไหล มีอัตโนมัติ / คมชัด / สมดุล / ประหยัด พร้อมจำค่าที่เลือก โหมดอัตโนมัติปรับภาพและเอฟเฟกต์ตามเครื่องโดยยังจำลอง NPC ครบตามจำนวนที่เลือก เดสก์ท็อปใช้ปุ่มดูเต็มฉากเพื่อซ่อนแผง

โหมดวางไฟรับการแตะหรือคลิกสั้น ๆ; ลากหมุนฉากไม่เพิ่มจุดไฟ และมีปุ่มยกเลิก

เมนูมุมมองอาคารเลือกได้ทั้ง **ภายนอกอาคาร / เปิดอาคาร / ภายในชั้น** เมื่อเลือกภายในชั้นให้เลือกชั้น 1–9 และใช้ปุ่ม **ห้องเรียน** เพื่อดูโต๊ะ เก้าอี้ กระดาน และทางเดินระยะใกล้ กลับภายนอกด้วยปุ่มอาคาร

### เดินสำรวจบนมือถือและ iPad

กด **เดินสำรวจ** ในแถบมุมมอง จอยซ้ายใช้เดินหน้า ถอยหลัง และเดินข้าง ลากบริเวณขวาของฉากหรือแผงรูปดวงตาเพื่อหันมอง ใช้สองนิ้วเดินและหันพร้อมกันได้ ปุ่มความเร็วสลับเดินปกติ/เดินเร็ว และปุ่ม × กลับมุมโมเดล

เปลี่ยนชั้นผ่านเมนูด้านบน: ลานโรงเรียน หรือชั้น 2–9 ระบบวางกล้องระดับสายตาและจำกัดการเดินชั้นบนตามห้อง/โครงข่ายทางเดิน การเปลี่ยนชั้นใช้เมนู ไม่ได้จำลองการเดินขึ้นลงบันไดของผู้สำรวจ คีย์บอร์ด WASD/ลูกศรยังใช้ได้ในโหมดนี้

### บทนำ 3 มิติสำหรับนำเสนอ (Cinematic Intro)

## ข้อจำกัด

ระบบนี้จัดทำเพื่อการศึกษา การพัฒนาอัลกอริทึม และการวิเคราะห์เชิงวิศวกรรมเบื้องต้น แบบจำลองความร้อนเป็นแบบเชิงประมาณ ไม่ใช่ CFD/FDS และผลลัพธ์ไม่ควรใช้แทนการวิเคราะห์โดยวิศวกรอัคคีภัยหรือแผนอพยพที่ผ่านการรับรอง การนำไปใช้กับสถานที่จริงต้องสอบเทียบมิติอาคาร ความกว้างช่องทาง จำนวนผู้ใช้อาคาร อัตราการไหล และข้อมูลด้านอัคคีภัยกับข้อมูลจริงก่อน

## ตรวจรายละเอียดบันได

เลือก **ภายในชั้น** และชั้นที่ต้องการ แล้วใช้เมนู **ดูบันได** เพื่อดูปีกซ้าย แกนกลาง หรือปีกขวา มุมภายในจะแสดงบันไดลงจากชั้นนั้นพร้อมชานพักและราวรอบช่องพื้น

สำหรับตรวจ geometry ตามแนวเส้นทาง เปิด `?intro=0&architecturalAudit=1` ในมุมภายนอก รายงานอยู่ใน `canvas.dataset.architecturalAudit` ขอบเขตและผลล่าสุดอยู่ใน `QA_REPORT.md` การตรวจนี้ไม่ทำงานในการใช้งานตามปกติ

## เปลวไฟและการสัมผัสของ NPC

ภาพไฟและ solver ใช้ flame cells ชุดเดียวกัน ต้นเพลิงเริ่มเล็กแล้วค่อยโต ไฟลามต่อเนื่องตามทางเชื่อม และบริเวณที่ลามผ่านแล้วยังไหม้อยู่ NPC จะถอยหรืออ้อมเมื่อไฟใกล้ รวมคนที่กำลังรอคิว สุขภาพลดเฉพาะสัมผัสเปลวไฟจริงต่อเนื่อง 0.9 วินาที พ้นไฟแล้วรีเซ็ต ควันและความร้อนมีผลต่อการรับรู้/การเลือกทาง ไม่ทำให้หมดสติเอง
